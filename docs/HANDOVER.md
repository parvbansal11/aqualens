# HANDOVER — Agent Execution Order and File Ownership

**Core rule: no two agents hold write access to the same area at the same time.** Ownership
transfers at explicit gates. An agent that needs a change outside its area raises it; it does
not reach across the boundary.

---

## 1. File ownership

| Path | Owner | Others may |
|---|---|---|
| `docs/**` | **architecture review** | read only; propose amendments, never edit |
| `configs/**` | **architecture review** | read; Codex may write only `configs/datasets/*.yaml` capability-gate values discovered at download |
| `packages/sagar/**` | **Codex** | Cursor: read only |
| `scripts/**` | **Codex** | — |
| `tests/**` | **Codex** | — |
| `data/**`, `runs/**`, `models/**` | **Codex** (generated) | Cursor: never |
| `apps/workstation/**` | **Cursor** | Codex: never, except the one file below |
| `apps/workstation/public/benchmarks.json` | **Codex** (generated by `make_benchmarks.py`) | Cursor: read only, never author |
| `README.md`, `docs/STATUS.md` | whichever agent completes a stage, at its gate | — |

**The two contracts that make parallel work safe:** `docs/API_CONTRACT.md` and
`docs/PRODUCT_SPEC.md`. Both are frozen. Neither Codex nor Cursor changes them; a needed change
comes back to the architect and is amended in the document *before* code follows.

## 3. Handoff protocol

Every handoff is a written note in `docs/STATUS.md` containing:
- what was completed, **verified how** (command run, observed output)
- what is `PARTIAL` and precisely what remains
- anything `BLOCKED`, with the blocker and its owner
- the next agent and its first task

**Report failures.** A stage that did not fully complete is handed off as `PARTIAL` with the gap
named. Handing off a broken stage as complete is the most expensive possible error here, because
the next agent builds on it.

---

## 4. Standing instructions for every agent

1. **Do not invent structure.** If it is not in `API_CONTRACT.md` or `PRODUCT_SPEC.md`, ask.
2. **No fabricated values.** No hardcoded detections, confidences, metrics or coordinates —
   not even as placeholders. An empty state is always correct; a fake number never is.
3. **Every derived value carries provenance and, when unavailable, `null` + a reason.**
4. **Never widen scope.** P1/P2 work does not start while a P0 is red.
5. **Respect the wording rules** in `CLAIMS_AND_EVIDENCE.md` for every user-visible string.
6. **Run the tests you can run** before handing off, and say which ones you ran.
